# Mini pet and temporary handoff — council decision

User change: a floating mini pet like Codex, with files held for roughly one minute and dragged out elsewhere. Stop at a useful checkpoint as weekly remaining approaches 40%; retain the earlier maximum 50-point expenditure from the 90% build baseline. Latest meter before packaging: 67% weekly remaining, 1% of the five-hour window remaining.

Three independent planners proposed native Windows widgets, reviewed the same alternatives after the file-handoff requirement arrived, and unanimously ranked native Win32/OLE first, tiny WebView plus native OLE second, and reuse of the main panel third. No model diversity is claimed. Parent selected the native approach because file drag-out requires native integration either way and an always-visible WebView would add browser overhead. Actual resource results must be measured, not inferred from window size.

Implemented: static original placeholder pet, separate lazy tools panel, transparency, always on top, click to open, movement, hide/show/reset, persisted/clamped position, one batch of at most 20 existing local paths, 60-second monotonic hold, copy-only OLE source, native shell file data, cancellation and an immutable transfer snapshot that survives expiry. No file contents are stored or uploaded. Originals are never moved or deleted by the hold logic. Virtual attachments and network-share paths are excluded.

Review identified and corrected a late-initialization timeout that could orphan the pet. Root also corrected capture-release ordering for click handling. Native appearance was inspected through the supported UI tool. Windows shell file-data roundtrip, Unicode paths, original-content preservation, bounds, expiry calculation and drag-source cancellation pass tests. Live cross-window transfer and actual countdown expiry remain manual acceptance work: the UI tool refused the drag endpoint because it was over another app's window. This limitation is not evidence that transfer succeeded or failed.

Primary API evidence: Microsoft's [OLE drag/drop overview](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/shell/dragdrop.md), [RegisterDragDrop](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-registerdragdrop), and [Shell Data Object](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject). Installed Windows crate 0.62.2 bindings were inspected directly. OLE initializes and pumps messages on a dedicated native thread; shell data uses standard local-file formats.

Next manual acceptance: drop two disposable files onto the pet; drag into a different Explorer folder; compare copied content and confirm originals remain; cancel a drag; wait 60 seconds and confirm the pouch empties; check Alt-drag, hide/show, position reset, mixed-DPI monitors and sleep/resume. Custom artwork/animation is deferred.
